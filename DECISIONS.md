# Decisions

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-10-12 | **Single package** (not a monorepo); `src/shared`, `src/server`, `src/web`, `src/electron`. | Simplest build; shared types imported directly; esbuild/vite handle each target. |
| D2 | 2026-10-12 | **SQLite via built-in `node:sqlite`** instead of better-sqlite3. | Electron 44 ships Node 24.21 (same as dev Node); `node:sqlite` works in both, so no native module ABI rebuilds between tests and the packaged app. Verified in-session. |
| D3 | 2026-10-12 | **scrypt** for PIN hashing (N=16384, r=8, p=1, 16-byte salt) instead of Argon2id. | Node 24 has `crypto.argon2Sync`, but Electron's BoringSSL reports "Argon2 algorithm not supported" (verified). scrypt is a salted, memory-hard KDF built into both runtimes. |
| D4 | 2026-10-12 | **Fastify + @fastify/websocket**, server runs **in the Electron main process**. | No separate Node runtime to ship; automatic start/stop with the app. |
| D5 | 2026-10-12 | **Pure engine + derived scores**: scores are the sum of non-voided events. | Auditable, no double-counting, undo/corrections by voiding events. |
| D6 | 2026-10-12 | **Competitor abstraction** (solo player or team) owns game points. Contributions are statistics-only deltas. | Meets team-scoring rules (no duplicated points) with one code path for solo and team games. |
| D7 | 2026-10-12 | Boards stored as **JSON documents** (`boards.content_json`) + `board_versions`; history uses normalized `game_clues` snapshots. | Editor works on whole documents (rearranging, import/export) easily; history still has relational, immutable clue snapshots. |
| D8 | 2026-10-12 | Undo snapshots only **gameplay fields** (phase, clue, buzzer, final, timer, …) — not roster/bindings/rules. | Undoing a judgement should not revert unrelated setup edits made later. |
| D9 | 2026-10-12 | Host authentication by **pairing code** shown on the desktop + long-lived host session; loopback may self-authenticate (toggle). | iPad reconnects without repeating setup; nothing secret in public QR codes. |
| D10 | 2026-10-12 | **Joy-Cons via WebHID** in the Electron renderer (no node-hid). | No native module; Chromium WebHID is maintained; Electron can auto-grant device permissions; same code testable in Chrome. |
| D11 | 2026-10-12 | Default Joy-Con mapping = **any button** except Home/Capture/+/−/stick clicks; per-controller override. | Easiest for non-technical players; held/edge handling prevents repeats. |
| D12 | 2026-10-12 | Shared-buzzer teams buzz **only** through a device bound to the team; members' phones are rejected. | "One buzzer represents the team"; prevents accidental multi-device buzzing. |
| D13 | 2026-10-12 | Phones are implicit controllers (`phone:<profileId>`), no assignment needed. | Minimal setup for the common case. |
| D14 | 2026-10-12 | Built-in avatars use **system emoji**; sounds are **synthesised with Web Audio**. | No third-party artwork or audio files to license; works offline. |
| D15 | 2026-10-12 | Simultaneous buzzes resolved by **server arrival order** (no tie window). | Deterministic; client timestamps are untrusted per spec. |
| D16 | 2026-10-12 | Statistics count only **completed** games. | Avoids partial/abandoned games skewing averages. |
| D17 | 2026-10-12 | Profile deletion is a **soft delete** that clears personal data but keeps the id. | Other players' history stays consistent. |
| D18 | 2026-10-12 | Restore-from-backup is applied **on next start**. | Avoids swapping the live DB under open connections. |
| D19 | 2026-10-12 | **Early-buzz detection = buzz while the question is showing, the answering opportunity is not over, and buzzers are locked.** Not early: after time ran out / host ended answering / already answered. Penalty rule (`none`/`lockout`/`clue`/`points`) is read at buzz time. | Server-authoritative, device-independent; avoids penalising late presses (AF8). Rule changes apply from the next buzz and never rewrite earlier events. |
| D20 | 2026-10-12 | Early-buzz **lockouts are keyed by person** (`p:<profileId>`) or by team for shared buzzers (`c:<competitorId>`), not by controller id. | Switching device must not dodge a penalty; a teammate with an individual buzzer is not punished for someone else. |
| D21 | 2026-10-12 | Point penalties are **charged once per player per clue** (plus a short anti-mash lockout) and refunded by voiding the event and re-recording an unpenalised early buzz. | Fair; keeps the audit trail and the early-buzz statistic. |
| D22 | 2026-10-12 | Phones are **"armed" while buzzers are locked** (button pressable, dimmed) instead of disabled. | Same early-buzz semantics as Joy-Cons/keyboards (AF7). |
| D23 | 2026-10-12 | New clue sub-state `answeringEnded` instead of new phases. Reveal/close/endAnswering accept an optional `clueId` and are ignored when stale. | Minimal change to the phase machine; stale double taps cannot close the next clue. |
| D24 | 2026-10-12 | Category introduction is **server-authoritative state** (`intro: {roundIndex, step, auto}`), auto-advance paced by the GameManager. | TV, host and any second display stay in sync; reconnecting displays resume at the right step. |
| D25 | 2026-10-12 | Saved games are **normalised on load** (`normalizeState`) rather than migrated in SQL. | State is a JSON document; normalisation is lossless and also covers undo snapshots from older versions. |
| D26 | 2026-10-12 | Client store applies **structural sharing** to each state broadcast. | Unchanged subtrees keep identity → fewer re-renders on iPhone/iPad without throttling authoritative updates. |
| D27 | 2026-10-12 | Phone portal uses **URL routes under /join/** with a drawer + back arrow; app shells are `100dvh` with internal scrolling and safe-area padding. | Browser Back works; no fixed bars resized by Safari's collapsing toolbars; nothing hidden under the notch. |
| D28 | 2026-10-13 | **Lobby-first startup**: a lobby session (server `LobbyManager`) exists before any game; host pairing codes belong to the lobby and stop working when it closes; the host pairing QR carries the code in the URL **fragment** (`/host#pair=`), is only served to host sessions, and the fragment is removed after use. | Matches the requested flow (Create lobby → pair iPad → set up → Open lobby → Start); the fragment is never sent to the server in request URLs or logs; the player QR stays credential-free. |
| D29 | 2026-10-13 | **One host app for iPad and PC** (`/host/*`), the desk pages reused inside it; `/desk` reduced to a start screen. | Same navigation and look on both devices, no duplicate UIs to maintain; old links keep working via redirects. |
| D30 | 2026-10-13 | **Server-built presentation state**: the host sends only `{page, view?, metric?, profileId?, boardId?}`; the server computes the public payload and sends it to host + TV roles only. The client toggles "Present on TV" (default on while a lobby is open, never during play). | The TV can never show host-only data even if the host page is private (answers, PINs, settings, device ids); privacy rules ("keep my stats private") are applied in one place. |
| D31 | 2026-10-13 | Lobby **mode change keeps everyone** and personal buzzers; only team-level (shared) buzzers are released, after a confirmation that says exactly what will be reset. Board change is a server-only engine action (`setBoard`) because the board comes from the database. | Changing settings in the lobby should never silently drop players; the warning names what is lost. |
| D32 | 2026-10-13 | The start screen connects as an **observer** host (`hello.observer`) so the lobby's "host connected" means a real host controller. | Otherwise the start screen itself would always count as the host. |
| D33 | 2026-10-13 | TV effects live in one public app setting `tvFx` (board intro + speed, unlock indicator, sound pack/cues/custom files) shared by server, TV and Settings via `src/shared/tvFx.ts` with normalisation. Custom sound files are only set through `/api/sounds/:cue` (sniffed audio, size cap). | One contract for three features; older saves fill in defaults; a settings save can never point the TV at an arbitrary file. |
| D34 | 2026-10-13 | The board intro (checker reveal) is part of the existing round-intro step -1 on the TV rather than a new engine step. | Skip/replay/auto pacing already exist and stay server-authoritative; no change to saved games or the intro contract. |
| D35 | 2026-10-13 | Built-in sound packs stay **synthesised** (Classic, Arcade, Soft); hosts may add their own files. | No recordings to license, nothing copyrighted, fully offline. |
| D36 | 2026-10-13 | Tournament standings (TV, phones) show every participant by name, including players who keep their statistics private; only names, colours/avatars and points are shown. | Standings are game results (already announced on the TV at each game's end), not personal statistics; hiding a participant would make the ranking wrong. Detailed statistics stay private. |
| D37 | 2026-10-13 | Joy-Con feedback and Identify are routed by the server to the window that reads the device (`controllerFx` message). | The host may be on the iPad, which has no Joy-Cons; previously Identify silently did nothing there. |
| D38 | 2026-10-13 | **Return to Lobby** creates a *new* game record (copied competitors, bindings, unassigned players, room code, rules, mode; board re-read from the library) instead of resetting the finished game in place. | Every match stays a separate, immutable history record with its own events and statistics; nothing in the completed game is rewritten. Competitor ids are reused so shared team-buzzer bindings stay valid. |
| D39 | 2026-10-13 | Clue media pickers list **explicit extensions + MIME types per kind** (`src/shared/mediaTypes.ts`), with separate Image / Audio / Video buttons; the server checks the chosen kind (`/api/media?kind=`). | With only `image/*,audio/*,video/*` Chromium on Windows built the dialog filter from the registry and opened on images. Audio-only MP4/WebM is accepted from the Audio button. |
| D40 | 2026-10-13 | The TV's "Previous page" is server state (`PresentRequest.back`, one level of history kept by LobbyManager). | Works from any host device, survives host reconnects, and no client needs to know what the TV showed before. |
| D41 | 2026-10-14 | Lobby crown = winner(s) of the previous match **in this lobby session** (memory only, cleared when the lobby closes); a separate medal = most total wins among the players present, shown only when it singles someone out (not when everyone ties) and never for private players. | The user preferred the reigning-winner crown; an all-time marker must not be misleading. |
| D42 | 2026-10-14 | Computer opponents never judge themselves: they send `submitAnswer` (text), which stops the answer timer and waits for the host's normal Correct/Incorrect. Bot answer texts come from an injectable async `answerSource` (local generator by default). | The host is the authority (R3-10/13); the async source lets AI bots (R3-14) plug in without changing the engine. |
| D43 | 2026-10-14 | AI answers use the official `@anthropic-ai/sdk` from the game server only; the key lives in `data/secrets/` (never the DB, so never in backups/exports), encrypted with Electron safeStorage in the Windows app; clients only learn `keySaved`. Each bot opts in ("AI answers"); every failure path returns an offline answer (or a pass) with a host-only note. | Keeps the game fully playable offline, keeps the key off every client and out of shared files, and makes costs opt-in per bot with a per-game cap. |
| D44 | 2026-10-14 | **Jeopardy!/Buzzinga sound pack = the owner's files, never redistributed.** `new_sfx/` is git-ignored; the server reads a pack from `<data>/media/soundpacks/buzzinga` (installed in Settings) and from a bundled folder (`new_sfx/` in development via `--sfx`, `resources/soundpacks/buzzinga` in a *local* build via electron-builder `extraResources`). Files are matched to cues by name (`PACK_FILE_RULES`); cues without a file play the Classic tone. | The recordings are user-provided and may be copyrighted (R4-1 §2.6). CI never has the folder, so public releases work without it; a local build includes it for personal use only. |
| D45 | 2026-10-14 | **Settings v2 migration:** tvFx saved before v2 with `soundPack: 'classic'` (or none) moves to Jeopardy!/Buzzinga and `unlock.style: 'edges'` moves to Bottom Glow; Arcade/Soft/Custom/Muted and other styles are kept. From v2 on every value is treated as explicit. | Classic and side edges were the defaults and were saved along with any other change, so an explicit choice cannot be told apart from an untouched default; the user asked for the new defaults. |
| D46 | 2026-10-14 | **Final Jeopardy! reveal order** is fixed when the Final starts: ascending pre-Final score, ties in the game's competitor (join) order. Wagers and answers are hidden from *every* role (host included) until their reveal step; the host event list redacts them too. When the think timer runs out the answers close and the reveal starts automatically; each written answer is recorded as a `submission` event (result `final`) for history. | R4-2 requires privacy from the host and a deterministic order; recording the text at close keeps history complete without changing statistics (`answer` events with note `final`). |
| D47 | 2026-10-14 | **Category introduction gates clue selection** in the engine (`selectClue` fails while `state.intro` is set); the host sees a dedicated intro screen instead of the board. Turning the "Introduce categories" rule off is the explicit opt-out. | Server-authoritative (R4-16): no client can open a clue early. |
| D48 | 2026-10-14 | **Lobby session persisted** (`settings.lobbySession`: name + created time) and restored together with the recovered game after a restart (new host pairing code); Return to Lobby re-opens a lobby if none is open. | Investigating R4-20: the lobby lived only in memory, so after a restart Return to Lobby led to a game without a lobby (TV "Getting ready", no join QR). The Results back arrow (which quietly closed the game = new lobby) was removed. |
| D49 | 2026-10-14 | **Board fill and its sound share one timeline**: the TV starts the board-fill cue and the checker reveal in the same render, stretched to the decoded clip length (`revealTimeline`); `IntroState.at` (server time) lets a reconnecting TV skip both. | R4-19: no drift between independent timers, no replay after reconnects; still completes without audio. |
| D50 | 2026-10-14 | **TV fonts:** bundled OFL look-alikes (Merriweather for Korinna-style clues, Anton for Swiss 911-style categories/values, via @fontsource, offline); licensed originals are used automatically when installed in Windows (CSS `local()` names) or placed as `<data>/fonts/clue|category|value.*`. **Clue background:** recreated with CSS gradients + an SVG noise tile instead of shipping the provided JPEG. | Commercial fonts and the screenshot-like image cannot be redistributed (R4-17/18); CSS scales to any resolution and costs nothing per clue. |
| D51 | 2026-10-14 | One navigation order in `src/shared/navigation.ts` (Home, Boards, Players, Teams, Buzzers, Leaderboards, History, Tournaments, Settings, Help) drives the host nav and the TV rail; the TV calls Home "Lobby". | R4-9: the TV rail had a different order. Tournaments sits next to Leaderboards (not in the user's list). |
| D52 | 2026-10-14 | **Lobby colours** live in the game state (`playerColors`, `colorPrompts`) and are assigned by the engine after every action: preferred colour if free, else the first free palette colour plus a phone prompt; the server's sequential processing makes simultaneous joins safe. All projections show the lobby colour; the profile colour is only the preference (changing it mid-game also changes the lobby colour when free). Beyond 24 palette colours, golden-angle generated dark colours. | R4-13: distinct colours without ever blocking a join; no client decides colours. |
| D53 | 2026-10-14 | **Second AI provider = any OpenAI-compatible `/chat/completions` server** (plain `fetch`, no SDK): local Ollama/LM Studio by default (`http://127.0.0.1:11434/v1`, no key, no internet), or a cloud service with a key. Only http(s) addresses; host-only setting. JSON mode requested, and a JSON object embedded in prose is accepted because small local models often add text. | Fits the offline-first goal (AI answers without internet or cost); one small code path covers Ollama, LM Studio, llama.cpp and hosted compatible APIs. |
| D54 | 2026-10-14 | **AI board drafts** are ordinary boards (tag `AI-generated`, description warning, note "AI-generated — check before playing" on every AI clue); the validator is lenient — empty, short or duplicate-answer clues become blank slots instead of failing the whole draft. Generation does not require the bot "AI answers" switch, only a configured provider. | Spec §19: clearly identify AI content, manual fallback for every AI operation (the editor), no mandatory cloud API (local provider). |
| D55 | 2026-10-15 | **Undo in Final Jeopardy!**: players' own wagers/answers (actor ≠ host) are never undo steps, and the think timer running out is one ("Final answers closed"). When Undo restores the answer stage (or the wager stage) that stage's timer **restarts from its full duration**, running; answers/wagers given before the undone step are kept. Everywhere else Undo still restores timers paused. | R5-15: before, Undo after time ran out restored a paused, nearly-empty timer (or skipped back two stages because the last undo step was a player's autosave). A fresh full timer is predictable for everyone and synchronises through the normal state broadcast. |
| D56 | 2026-10-15 | **Default picture ≠ deleting the upload**: `profiles.picture_off` (migration v6) hides an uploaded picture; the file is deleted only by an explicit delete, a replacement upload or profile deletion. Public views see no picture while it is off; the owner/host see `uploadedPictureUrl` to switch back. | R5-16: browsing or choosing a default picture used to delete the uploaded file. |
| D57 | 2026-10-15 | **Daily Double! wager owner** = the competitor in control when the clue was picked (`clue.wagerBy`). The phone sends `submitDailyWager` (validated like the host's, no undo step); the host locks it with `setDailyWager`, which shows the clue. In a team the first member to enter the wager owns it until it is locked; teammates see it read-only. The host can still enter a wager for any competitor (recovery). | R5-20 wants a player-driven flow with the host still deciding when the clue appears, without conflicting team submissions. |
| D58 | 2026-10-15 | **Sound folders found automatically**: the server merges every existing bundled folder (personal-build resources, then `Sounds`/`new_sfx`/`OfflineJeopardy Sounds` next to the exe, the portable exe or in the data folder); installed files still win; per cue the first folder wins. Public releases still contain no recordings. | R5-9: the owner's recordings cannot be redistributed in GitHub releases; dropping one folder next to the app (or one "Add a folder" import, kept in the data folder across updates) is the closest to "works immediately". |
| D59 | 2026-10-15 | **Create Lobby = lobby + game in one step** (R5-4): the game starts in its lobby phase with the most recently used game's board, mode and rules (any status); the host changes them in the lobby. A lobby closed before anyone joined is discarded (status abandoned). The game computer's Create lobby does the same. | The separate "Set up a game" screen duplicated the lobby; reusing the last settings makes a second game night one tap. |
| D60 | 2026-10-15 | **Team slots** (R5-5): team games start with ceil(players/2) empty teams (2 when nobody is there yet) named after TEAM_COLORS ("Blue Team"…); players wait in Unassigned and pick a team themselves (lobby only, within `rules.maxPerTeam`); the host may over-fill (highlighted, start blocked). At the start empty slots are dropped (kept in `lobbyTeams` for Return to Lobby) and unassigned players stay in the lobby without playing. Switching to individuals keeps the team setup in `teamDraft`. Playing teams without a saved team are linked to one at the start (same name + same members, else a new saved team) so team statistics accumulate. | Spec R5-5; team statistics are keyed by saved team ids. |
| D61 | 2026-10-15 | **Lobby nicknames** live in the game state (`nicknames`), unique per lobby, copied on Return to Lobby. Projections put them into `profiles[].nickname` for every role, so every screen shows the nickname; the profile name stays in `name` and is shown in parentheses where the spec asks (TV lobby, host lobby, phones) — never on the TV buzz-in. The permanent profile nickname is no longer used in games. | R5-17.5/6/7: temporary, never overwrites the profile. |
| D62 | 2026-10-15 | **AI providers registry** (R5-11, by the Gemini work): `src/server/aiProviders` (anthropic, openaiCompat, gemini); AiService keeps all game logic. Gemini via its official REST API with plain fetch; key only in the `x-goog-api-key` header; no hardcoded Gemini model (list from models.list, Test picks a Flash model); per-provider key files (old single key migrated); a 429/quota pauses the provider (retryDelay / Retry-After / 60 s / until midnight Pacific for daily quotas) and bots answer offline meanwhile. | Offline-first, no key leaks, provider quotas respected. |
| D63 | 2026-10-15 | **Parallel development with git worktrees**: milestones E (host gameplay), F (TV polish) and G (AI) were built by agents in `.claude/worktrees/*` (git-ignored) and merged into main; Playwright takes `E2E_PORT` so several checkouts can run their suites at once. | Faster delivery without file clashes. |
| D64 | 2026-10-17 | **Fair buzzer timing (supersedes D15, amends D19):** the server still decides, but a press carries the device's own timestamp. The server measures each phone's / the TV window's clock offset itself (probes; min-RTT sample), moves a press earlier than its arrival by at most min(cap, measured delay) — cap 50 ms for phones (100 "slow Wi-Fi", 0 = arrival order), 30 ms for the Joy-Con/keyboard bridge — and waits at most 60 ms (only as long as another connected, eligible device could still have pressed earlier). Early-buzz detection uses the corrected press time but penalises only when certain beyond the uncertainty; otherwise the press counts at the unlock. "N ms before you" only when the gap exceeds both uncertainties and 25 ms. | R6-16…24 research (docs/BUZZER_FAIRNESS_RESEARCH.md): arrival order systematically favours fast Wi-Fi; client timestamps are bounded hints (a liar gains ≤ cap), not trusted values. Simulated: correct winner on callable gaps 83–89 % → 96–98 %, median added wait ≈ 27 ms. |
| D65 | 2026-10-17 | **Final Jeopardy! answers close into a `closed` stage** (timer removed, nothing revealed) and the host starts the reveal with **Begin Answer Reveals**; early "Close answers" goes to the same stage. Undo from `closed` re-opens answering with a fresh timer (D55). | R6-6: the timer used to stay on the TV and the reveal started by itself. |
| D66 | 2026-10-17 | **One score-change presentation on the TV:** the score box itself shows "+$600" / "−$600" for 1.3 s, then the new total (with the theme prefix, e.g. "$3,000"); no side labels or verdict pills. | R6-5. Scores on the TV now carry the "$" prefix to match the change. |
| D67 | 2026-10-17 | **TV swipes run on the compositor**: swiping layers get `will-change: transform` and animate whole `transform` strings (motion → WAAPI). | R6-15: profiling showed every swipe frame re-rasterised the full 1080p card (docs/PERFORMANCE.md). |
| D68 | 2026-10-17 | **Quiet score changes (R7-11):** every role's view carries `scoreCause` = the latest score-changing event; `score_adjust` (manual adjustments, penalty refunds) and `undo` are quiet — the TV plays no correct/incorrect sound and the score box shows the new total without the ±$ swap. Final judgments sound from the judgment itself (once), not from the score delta, so a $0 wager still sounds (R7-8). | Manual corrections are not gameplay; undoing a correct answer used to play the "incorrect" sound. Bots often wager $0 in the Final. |
| D69 | 2026-10-17 | **App shells pinned with `position: fixed; inset: 0`** (was `height: 100dvh`) and the document locked (`html:has(.app-screen)` overflow hidden); after the on-screen keyboard closes a stray document scroll is reset. | R7-19: in real iPad Safari a swipe on a short page or a focused field could scroll the document, collapse the toolbars and leave the shell offset (Present on TV cut off). A fixed shell always equals the visible layout viewport. |
