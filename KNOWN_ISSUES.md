| K27 | Bots | ~~Bots do not advance rounds~~ — **practice games now move to the next round / Final Jeopardy! / results by themselves (session 6)**; in ordinary games the host decides. On boards with very few clues an offline wrong answer may be "Pass". | — |
| K28 | Sound pack | The Jeopardy!/Buzzinga recordings in `new_sfx/` are the owner's files: git-ignored, never in public releases (no redistribution rights). | K33 | TV lobby | The join QR is now ~60 % of its former size (R5-3.2) with a ~2-module quiet zone; scanning distance on a real TV was not re-measured. | Players can type the address shown under the code; the host can show the large join QR on the TV from the game menu. |
| K34 | Host layout | The iPad clue/board/intro redesign (R5-12…14) and the host sidebar now hidden below 1024 px were checked in WebKit emulation (iPad Pro 11 portrait/landscape), not on a real iPad. | Report anything that looks off. |
| K35 | Buzzer timing | Fair timing (D64) corrects network delay, not differences between input hardware: phone touch screens of different models and the Joy-Con Bluetooth path can differ by ~10–20 ms, which no software can see. Gaps under ~25 ms show "Very close buzz!". Results come from simulations and local sockets — **not measured with real phones on a real Wi-Fi network or real Joy-Cons**. Phones on very slow links (best round trip > ~120 ms) or that just reconnected are decided by arrival. | Host → Rules → Advanced → "Who buzzed first" → "First to arrive" restores pure arrival order. A slow-motion video of two phones pressing together would measure the hardware bias. |
| K36 | TV performance | Category swipes measured with Chromium on this PC (software raster, 4× CPU throttling and the GPU) — not on the player's TV PC or a TV box (docs/PERFORMANCE.md). The first board fill when the game replaces the lobby still has one long frame (~160–190 ms) while the game screen mounts. | Settings → "Reduce motion on the game board" if an old PC still stutters. |
| K37 | Phone buzzer | The full-screen buzzer, colours and touch handling were checked in Playwright phone emulation, not on real iPhones/Android phones. | Report anything that scrolls, zooms or misses taps. |
| K38 | iPad Safari | The R7-19 shell fix (fixed shell, locked document, keyboard scroll reset) is verified in WebKit emulation at Safari/web-app sizes and with simulated toolbar resizes only — emulation has no real Safari toolbars or keyboard. | Report if the host app still shifts on the real iPad (which page, Safari or Home-Screen app, orientation). |
| K39 | Apple TV + Steam Link | Joy-Cons paired to an Apple TV reach the PC only as Xbox-style pads, and only when OfflineJeopardy is started from Steam (non-Steam game, Steam Input on); tvOS joins an L+R pair into one controller (split: hold Capture + Home); max 4; no Identify/vibration; extra latency. Research only — not tested with the hardware (docs/JOYCON_APPLETV_STEAMLINK.md). | Recommended: a USB Bluetooth adapter on the game PC (or a Bluetooth laptop on the TV) so the normal Joy-Con path works; phones always work. |
| K40 | Lobby phone delay | The delay on the TV lobby cards (R7-4) is the server-measured round trip of the phone's connection (smoothed, 5 ms steps), checked with local sockets and Chromium only — not with real phones on a real Wi-Fi network. Joy-Cons show "Bluetooth" without a number (their delay cannot be measured from the PC). | Display only: buzzing never uses this number. Report odd values (e.g. a phone stuck on "measuring…"). |
| K42 | Clue sound length | The server knows when a clue's sound or video has finished from the length the host's browser reads (it starts "after the media" buzzers and the Final think time). WebKit on Windows (the iPad emulation in the tests) sometimes reads a 2-second WAV as 1 second; real iPad Safari is untested. The TV now lets a sound that is still playing finish, so it is never cut off — only the think time / automatic unlock can start that much early. | Prefer MP3/M4A files; the host can also start the think time by hand. A later fix could read the length on the server at upload. |
| K43 | Tests | The socket buzzer-timing test (tests/integration/round6 "the press made first wins even when it arrives second") simulates two presses 15 ms apart over real localhost sockets with clock sync; it fails about 1 run in 10 on its own and more often when the PC is busy (other suites in parallel). The engine's arbitration is unchanged and covered deterministically by tests/unit (buzzTiming, buzzFairness.sim). | Re-run the file on its own; a failure that repeats is real. |
| K41 | Score editor | "Remove Player" in the iPad score editor works only for a player or team without points in this game (the engine refuses otherwise, so finished-game history stays consistent). | Set their score to 0 with the editor, or remove them in the lobby before the next game. |
